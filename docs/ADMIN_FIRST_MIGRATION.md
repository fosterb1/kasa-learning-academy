# First CMS database migration — verified staging release

Kasa Learning Academy's Vercel deployment currently builds successfully. However, `/admin/login` fails because Neon production lacks the Payload CMS tables (`users`, `users_sessions`, `lessons`, etc.). The original PostgreSQL error is **42P01**, missing relation.

## What's included

- `src/migrations/20261117_072144.ts`: generated by Payload 3.93 against a fresh Neon staging branch
- `src/migrations/20261117_072144.json`: matching Drizzle schema snapshot (21 tables)
- `src/migrations/index.ts`: registers the initial migration

The UP migration was inspected: **142 non-destructive SQL statements** (12 CREATE TYPE, 21 CREATE TABLE, 20 ALTER TABLE, 89 CREATE INDEX). It ran successfully as a transaction on Neon staging branch `academy-staging`, where all core tables were verified. **It has NOT been applied to production yet.**

## Apply once to production with Payload CLI

Important: use `payload migrate` rather than manually replaying SQL against production. The Payload CLI also tracks migration names and batches, avoiding duplicate execution on later deployments.

1. Keep the Vercel site protected while the first administrator is being created. `/admin/create-first-user` must not be claimed by another visitor.
2. Clone the latest `main` branch **after this migration has been merged** onto a trusted machine with Node.js 24.x.
3. Copy `.env.example` to an untracked `.env.local`. Set `DATABASE_URL` to a **direct (non-pooled)** connection from Neon project `kasa-learning-academy`, default `main` branch, `neondb`. Set private `PAYLOAD_SECRET` (32+ characters). Set `NEXT_PUBLIC_SITE_URL=https://kasa-learning-academy.vercel.app`.
4. Run from the project root:

```bash
npm install
npm run db:migrate
npx payload migrate:status
```

5. Confirm Neon production now contains `users`, `users_sessions`, `modules`, `lessons`, `challenges`, `guides`, `announcements`, `payload_migrations`. Do not run `migrate:fresh` or `migrate:reset` in production.
6. Immediately open `https://kasa-learning-academy.vercel.app/admin/create-first-user` **while protected by your Vercel account authentication**, and register the very first user with your own strong, private password. Payload's first-user operation bypasses normal access rules only when zero users exist. Alternatively use the private `npm run bootstrap:admin` script after setting `ADMIN_EMAIL` and `ADMIN_PASSWORD` in `.env.local`.
7. To load the curriculum, set `SEED_CONTENT=yes` in `.env.local` then:

```bash
npm run seed
```

8. Verify public routes `/`, `/learn`, `/practice`, `/guides`, and the login at `/admin`. Edit an example lesson, Save Draft and Publish in the admin dashboard. Keep browser code execution confined to its existing worker.

## Operational cautions

- Never paste a database URL or password into ChatGPT, a GitHub issue, or a public terminal log.
- The Vercel production `DATABASE_URL` is already configured as an encrypted pooled Neon connection. Don't replace it just to run migrations from another machine.
- The current public-learning fallback is temporary; as soon as tables exist, database content becomes authoritative and will be empty until the seed runs. Coordinate first-user registration and content seeding before announcing the launch.
- Future migrations should be generated and tested against a Neon staging branch first.
- Do not expose an unauthenticated setup/migration endpoint, and do not commit `.env.local`.
